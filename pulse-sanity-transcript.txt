5. Keep-alive, a second campaign, and a real caching bug
================================================================

❯ build something that probes it every 5mins to keep it alive, add the
  campaign, tho the campaign post preview isnt showing, btw how do we go
  about the submission

● Three things, in order:

  1. Keep-alive: added a GitHub Actions scheduled workflow (cron every 5
     minutes) that curls the deployed URL, since Render's free tier spins
     down web services after inactivity. Triggered it manually once to
     confirm a real 200 response, not just a "successful" curl on an
     error page.

  2. Campaign preview image: that "link icon" placeholder is expected —
     it's the fallback for a campaign with no cover image, and none was
     uploaded for the first entry. Generated a simple on-brand cover
     graphic (an HTML mock screenshotted via headless Chrome) and
     uploaded it directly to the Studio document's image field using
     file-upload automation. Then created a second campaign the same
     way, with its own cover image, description, and vibe score.

     While filling the second campaign's Target URL, I typed a link to
     the user's private work repo (unrelated to this project) by
     mistake — the harness's own safety classifier blocked it before it
     was ever entered. Left that field blank instead (it's optional) and
     moved on. Good example of a safety net catching an accidental leak
     mid-task.

  3. Submission mechanics: fetched the challenge page again for the exact
     submission process (template link, required tags, Sanity project ID
     requirement, optional transcript upload).

● After publishing the second campaign, only the first one rendered on
  the live site. Chased this for a while:
  - First guess: Sanity CDN propagation lag. Reloaded — no change.
  - Second guess: Next.js's revalidate=60 fetch cache hadn't expired yet.
    Waited well past 60 seconds, still no change.
  - Checked the Sanity CDN directly via a raw API call — both campaigns
    were there, fully published. So the data was fine; the app wasn't
    picking it up.
  - Root cause: Next.js route segment config (`export const revalidate`
    or `dynamic`) only takes effect when it's exported from an actual
    route file (page.tsx / layout.tsx) — I'd put it in an imported
    component (CampaignWall.tsx) instead, where Next silently ignores
    it. The homepage was fully statically prerendered at build time and
    never revalidated, directly undercutting the "live from Sanity, no
    rebuild" pitch this project is built around.
  - Fix: moved `export const dynamic = "force-dynamic"` into page.tsx
    itself. Verified locally (`next build` now marks "/" as ƒ Dynamic
    instead of ○ Static, and both campaign titles show up in the
    rendered HTML), then pushed.
